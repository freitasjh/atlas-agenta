# ADR-003 — UI CadastroPage + validações cliente + ViaCEP com fallback

> Unidade de decisão: 1 ADR = 1 branch = 1 PR (merge humano).

- **Decisão**: Estender `CadastroPage` (`src/auth/CadastroPage.tsx`) + `signupSchema` (`src/lib/validations/auth.ts`) com razão social opcional, documento/telefone/endereço obrigatórios e `full_name` obrigatório, consumindo o contrato do ADR-002; ViaCEP como sugestão com fallback 100% manual; i18n pt-BR total; PII mascarada na UI.
- **Motivo**: Cadastro fecha dados da bilhetagem na origem sem repetir coleta (PRD §2); validação cliente dá feedback imediato mas nunca substitui servidor (RNF04); ViaCEP reduz digitação/erro no mobile sem virar dependência dura (RESEARCH T1-A).
- **Alternativas descartadas**: Endereço manual puro sem ViaCEP — fonte: https://www.gov.br/ds/ (GOV.BR Design System, custo de conversão por campo); descartada por pior UX mobile e mais erro de digitação (logradouro/cidade/UF à mão, sem checagem cruzada de CEP) — fonte: https://viacep.com.br/
- **depende-de**: ADR-002
- **Interface congelada**: Contrato de tela `/cadastro` (ordem dos blocos): 1. empresa (`trade_name!`, `legal_name?`, `document!` máscara dinâmica 11↔14, `phone_empresa!` máscara `(00) 00000-0000`); 2. endereço (`address_cep!` máscara `00000-000` → strip p/ 8 dígitos, `address_street!`, `address_number!`, `address_complement?`, `address_city!`, `address_state!` select 27 UFs maiúsculas); 3. acesso (`email!` único = login = `owner_email`, `password` + `confirmPassword` só cliente, regras inalteradas); 4. admin (`full_name!`, `segment?` enum inalterado). Corpo enviado à Edge (idêntico ao schema ADR-002, `.strict()`): `{ email, password, trade_name, legal_name?, document (só dígitos), phone_empresa (só dígitos), address_cep (8 dígitos), address_street, address_number, address_complement?, address_city, address_state (UF maiúscula), full_name, segment? }` — nenhum `whatsapp`/`role`/`tenant_id`. ViaCEP: `GET https://viacep.com.br/ws/{cep8}/json/` com debounce 400ms + timeout 5s, sem cache persistente; `{"erro": true}` ou CEP não encontrado ou timeout/rede ⇒ erro pt-BR por campo ("CEP não encontrado. Preencha o endereço manualmente.") e todos os campos ficam editáveis; sucesso ⇒ pré-preenche logradouro/cidade/UF (editáveis), número sempre manual; cadastro conclui com ViaCEP fora (fallback afirmado RF05). Validação cliente (react-hook-form + zod, mesmas regras servidor): DV CPF/CNPJ, telefone `^\d{10,11}$` pós-strip, CEP `^\d{8}$` pós-strip, UF nas 27 siglas; erros pt-BR por campo com `role=alert` + foco, mensagens via `react-i18next` (chaves `cadastro.*`, sem literal solto): "Informe o CNPJ ou CPF." / "CNPJ/CPF inválido." / "Este CNPJ/CPF já tem cadastro." (409) / "Informe o telefone da empresa." / "Informe seu nome." / endereço por campo. PII: exibir documento/telefone mascarados após digitação; nenhum valor sensível em console.log/testes com dado real. Testes (estender, sem inventar suite): `schemas.test.ts` espelhado cliente/servidor (DV válido/inválido, unicidade, fallback razão social, `.strict()` recusando `whatsapp`), `CadastroPage.signup.test.tsx` (ViaCEP ok/falha, 409 por campo, auto-login/redirect inalterados). Sem regressão: redirect pós-login, seed templates, RNF01 (sem regressão carga) / RNF02 mobile-first.
- **Fora desta decisão**: DDL (ADR-001); RPC/Edge server (ADR-002); whatsapp/Evolution; funcionário/convites (fase 2); autoagendamento/taxa-reserva/métricas; mascaramento além do afirmado vai a `security-review` no design.
- **Consequências se estiver errado**: Divergência cliente↔servidor (regex/DV/mensagem) gera erro só em produção direta; ViaCEP como autoridade (em vez de sugestão) trava cadastro offline — reversão = ajuste só neste ADR sem tocar RPC/DDL.
